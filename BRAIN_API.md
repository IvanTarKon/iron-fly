# Связь программы «мозга» с движением

[Первый запуск без опыта](docs/FIRST_START.md) · [Техническая инструкция](docs/CONTROL_GUIDE.md)

Отдельная программа получает решения нейросети и посылает их локальному серверу
симуляции. Один рабочий поток владеет MotionController и PyBullet; HTTP-запросы
попадают в очередь. Существующие FK/IK и генераторы походок не заменяются.

## Запуск

```sh
bash scripts/build.sh
.venv/bin/python scripts/simulation_ui.py --port 8766 --brain-speed 0.1 --brain-turn-rate 15
```

Интерфейс наблюдения: http://127.0.0.1:8766. Если прежний сервер уже занимает порт,
остановите его через `bash scripts/server.sh stop`, затем запустите новую версию.
`--brain-speed` задаётся в м/с, `--brain-turn-rate` — в градусах/с.
Базовая скорость положительная, максимум 0.2 м/с: остаётся запас для ×1.5
в пределах конфигурации 0.3 м/с. Предельные скорости не означают проверенную
устойчивость физической модели; начальное значение — 0.1 м/с (100 мм/с), с ускорением — 150 мм/с.

## Команды

POST `/api/brain`, заголовки `Content-Type: application/json`, `X-Muha-UI: 1`.
Тело содержит только поле `command`.

| command | Действие |
|---|---|
| `forward` | Вперёд относительно корпуса |
| `backward` | Назад относительно корпуса |
| `left` | Поворот налево на месте |
| `right` | Поворот направо на месте |
| `stop` | Остановка ходьбы с сохранением стойки |
| `jump` | Включить ×1.5 для движения вперёд/назад |
| `normal` | Выключить ускорение, вернуть ×1 |
| `start` | Снять блокировку после ошибки и разрешить движение; затем нужна команда направления |

Направление сохраняется до следующей команды направления или stop.
`jump` и `normal` изменяют только множитель. На месте jump не начинает движение;
во время поворота его скорость не меняется. Флаг ускорения сохраняется при смене
направления и после stop, пока не придёт normal. Сброс сцены выключает ускорение.
Прыжок здесь означает скорость команды ×1.5, без физического отрыва от земли;
фактическая скорость корпуса зависит от походки и контакта с поверхностью.

Первая команда направления автоматически отправляет start и ждёт готовности
стойки. Повторные start от мозга при обычном управлении не нужны.

```sh
python3 scripts/brain_client.py forward
python3 scripts/brain_client.py jump
python3 scripts/brain_client.py right
python3 scripts/brain_client.py normal
python3 scripts/brain_client.py stop
```

Из другой Python-программы (модуль `scripts/brain_client.py` доступен в PYTHONPATH):

```python
from brain_client import send_command
send_command('forward')
# Следующее решение нейросети, когда оно появится:
send_command('stop')
```

HTTP 202 означает постановку в очередь, а не завершение движения.
Состояние доступно через GET `/api/state`: `brain` показывает направление,
множитель, блокировку и настройки; `output` — реальное состояние контроллера;
`pose` и `position` — измеренную позу модели. Очередь имеет предел 32 запроса.

## Удержание команды и ошибки

Мозгу не нужно повторять команду: адаптер формирует свежую низкоуровневую команду
каждые 20 мс. Тайм-аут MotionController 0.5 с сохранён. Тайм-аут отсутствия браузера
не применяется, когда активен мозг. Отключение или зависание программы мозга
**не останавливает** движение: это выбранная семантика «до следующей команды».
Это пока локальная симуляция, не аппаратный watchdog.

Некорректный запрос к API мозга или переполнение очереди блокирует движение
на следующем рабочем такте; цикл продолжает работать. Ошибка ядра также блокирует
движение. Новые команды направления блокировку не снимают: нужен `start`, затем
направление. Запросы с недопустимым origin или без специального заголовка отклоняются
до обработки команд. Сервер слушает только 127.0.0.1, доступа с другого компьютера нет.

Кнопочная панель направлений использует тот же `/api/brain` и то же намерение.
Старые действия браузера start/move/stop/pause/reset забирают управление у мозга;
новая команда мозга забирает его обратно. Просмотр и heartbeat браузера не мешают
мозгу. Во время управления мозгом скорости берутся из параметров запуска, а не из
ползунков ручного управления. Походка остаётся текущей; менять её следует в ручном
режиме после остановки.

## Проверка

```sh
.venv/bin/python tests/test_brain_control.py
.venv/bin/python tests/test_motion.py
.venv/bin/python tests/test_simulation_ui.py
```

Последний набор создаёт локальный HTTP-сервер на свободном порту и проверяет
полный путь HTTP → очередь → MotionController → PyBullet, удержание команды без
heartbeat, stop, ошибки и возврат к ручному управлению. Исторические upstream-сбои
остаются отдельным результатом; новые тесты не объявляют полную приёмку робота.
