# Железная муха: первый запуск без опыта

Эта инструкция объясняет, что открыть, что скопировать и какой результат получить.
Если нужен протокол для разработчика — рядом есть [техническая инструкция](CONTROL_GUIDE.md).

## Сначала разберёмся, что вы запускаете

Сейчас есть программа движения шестиногого робота и его модель на экране.
Программа умеет рассчитывать углы ног. Она **ещё не управляет настоящими моторами**.
Для первого запуска не нужны Repka, провода или сервоприводы: достаточно компьютера.

«Мозг» — ваша отдельная программа, которая получает решение нейросети.
«Алгоритм» — наша программа, которая превращает решение «вперёд» в движение ног.
Нейросеть вам нужно подключить самостоятельно; внутри этого проекта её нет.

Связь выглядит так:

```text
Ваша нейросеть → ваша программа мозга → команда «forward»
                                           ↓
                            наша программа движения
                                           ↓
                             робот на экране компьютера
```

Мозг и алгоритм запускаются на одном устройстве. Между ними не нужно ничего
соединять проводами. Они обмениваются сообщениями по адресу `127.0.0.1:8766`.
Это адрес программы на вашем же компьютере, а не сайт в интернете.

## 1. Выберите свой вариант

| Что у вас | С чего начать |
|---|---|
| Windows 11 или Windows 10 версии 2004+ | С пункта 2: установить WSL |
| Уже есть Linux | С пункта 3 |
| Repka Pi, нужны только расчёты без картинки | С пункта 8 |
| Нужны настоящие моторы | Прочитать пункт 9: эта часть ещё не готова |

Проверен Linux x86_64 с Python 3.14.10. Windows через WSL — предложенный путь запуска,
ещё не проверенный на вашем Windows. Модель Repka и ОС пока не выбраны.

## 2. Только для Windows: подготовьте Linux внутри Windows

1. В меню «Пуск» найдите **PowerShell**.
2. Нажмите правой кнопкой и выберите **Запуск от имени администратора**.
3. Вставьте команду и нажмите Enter:

```powershell
wsl --install
```

4. Если потребуется, перезагрузите компьютер.
5. Откройте **Ubuntu** из меню «Пуск». При первом запуске задайте имя пользователя
   и пароль. При вводе пароля символы могут не отображаться — это нормально.
6. Дальнейшие команды с пометкой Bash вводите **в Ubuntu**, не в PowerShell.

WSL создаёт Linux-среду внутри Windows. Этот порядок установки указан в
[официальной инструкции Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install).
Если WSL уже установлен, повторно устанавливать его не нужно.

## 3. Установите инструменты и скачайте проект

Откройте терминал Linux или Ubuntu в Windows. Терминал — окно, куда вводят команды.
Копируйте содержимое серых блоков, без слов `bash` и без тройных обратных кавычек.
Выполняйте блоки по очереди. Если появилась ошибка — не продолжайте вслепую,
посмотрите пункт 10.

Для Ubuntu/Debian-подобной системы:

```bash
sudo apt update
sudo apt install git g++ python3 python3-venv python3-pip
```

`sudo` может запросить пароль вашего Linux-пользователя. Это не пароль GitHub.
Для другого Linux названия команд установки могут отличаться.

Теперь скачайте проект в домашнюю папку:

```bash
cd ~
git clone https://github.com/IvanTarKon/iron-fly.git
cd iron-fly
```

Репозиторий приватный. Получатель должен иметь доступ через свой GitHub-аккаунт.
Если написано `Repository not found`, сначала откройте репозиторий в браузере под
своим аккаунтом и попросите владельца добавить доступ. Для скачивания через Git
нужна настроенная авторизация GitHub. Не вставляйте ключи доступа в исходники или
команды, которые собираетесь кому-то переслать.

Если Git-авторизация пока не настроена, можно в браузере на странице репозитория
выбрать **Code → Download ZIP**, распаковать архив и открыть терминал в распакованной
папке. Она может называться `iron-fly-main`: далее вместо `cd ~/iron-fly` используйте
путь к этой папке. В ней должны лежать `README.md`, `scripts` и `src`. Git всё равно
понадобится для загрузки публичных компонентов следующей командой. Для ZIP-копии
обновление через `git pull` не работает.

## 4. Подготовьте проект — один раз после скачивания

Все команды этого пункта выполняются **в папке проекта**.

```bash
bash scripts/bootstrap.sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
bash scripts/build.sh
```

Что здесь происходит:

| Команда | Простыми словами |
|---|---|
| `bootstrap.sh` | Скачивает готовые компоненты нужных версий и применяет наш патч |
| `python3 -m venv .venv` | Создаёт отдельную папку Python-зависимостей проекта |
| `pip install ...` | Устанавливает библиотеки |
| `build.sh` | Собирает C++ алгоритм в файл, который сможет вызвать Python |

Для загрузки компонентов и библиотек нужен интернет. Виртуальное окружение
не нужно «активировать»: команды уже явно используют `.venv/bin/python`.
Не копируйте `.venv` и `build` с другого компьютера, особенно с ПК на Repka.

Зависимости закреплены в `requirements.txt`. Если pip сообщает, что версия не
найдена или не подходит к Python/архитектуре, сохраните полный текст ошибки и
вывод `python3 --version`; не заменяйте версии на случайные. Полный набор проверен
в указанном выше окружении, а не на всех версиях Ubuntu и ARM.

## 5. Запустите симуляцию и нажмите кнопки

В том же терминале:

```bash
.venv/bin/python scripts/simulation_ui.py --port 8766
```

Оставьте терминал открытым. Откройте браузер и введите в адресную строку:

**http://127.0.0.1:8766**

В Windows браузер можно открыть прямо в Windows: доступ к серверу WSL через localhost
описан в [документации Microsoft](https://learn.microsoft.com/en-us/windows/wsl/networking).
Мозг и сервер для первого опыта запускайте в одной Ubuntu/WSL.

Появится робот. Дождитесь состояния **«Стойка»**. Под картинкой есть панель
**«Управление роботом»**:

| Кнопка | Что произойдёт |
|---|---|
| ↑ Вперёд | Начнёт идти вперёд |
| ↓ Назад | Начнёт идти назад |
| ↶ Налево / Направо ↷ | Начнёт поворачиваться на месте |
| ■ Стоп | Остановит ходьбу, оставит робота стоять |
| Ускорение ×1,5 | Увеличит скорость движения со 100 до 150 мм/с |
| Обычная ×1 | Вернёт 100 мм/с |

Нажимать и держать не надо: **нажали один раз — команда действует дальше**.
Для остановки нажмите **■ Стоп**. Закрытие страницы не отменяет команду кнопочной
панели. Ускорение сохраняется даже после stop; чтобы его снять, нажмите «Обычная ×1».
«Прыжок» в коде означает это ускорение, робот не подпрыгивает.

Полезная первая проверка: «Вперёд» → подождать пару секунд → «Стоп».
Затем «Налево» → подождать → «Стоп». Активная команда подсвечивается.

Поля скорости справа относятся к отдельному ручному режиму. Если меняете именно
их: обычный «Стоп» под панелью → значения → «Применить параметры» →
«Движение по параметрам». Эти поля не меняют скорость кнопок-стрелок.

## 6. Как подключить свою программу мозга

Сначала запустите сервер по пункту 5. Затем откройте **второй терминал** в той же
Linux-системе. Первый терминал продолжает работать, не закрывайте его.

Во втором терминале выполните:

```bash
cd ~/iron-fly
python3 scripts/brain_client.py forward
```

Робот пойдёт вперёд. Чтобы остановить его:

```bash
python3 scripts/brain_client.py stop
```

Если это сработало, связь двух программ уже работает. Следующий шаг — заменить
ручной ввод команды решением вашей нейросети.

Для Python-программы найдите в проекте файл **`scripts/brain_client.py`** и скопируйте
его рядом со своим файлом мозга. Пример расположения:

```text
моя_программа/
    my_brain.py
    brain_client.py
```

В `my_brain.py` можно сначала написать такой простой проверочный пример:

```python
import time
from brain_client import send_command

try:
    send_command('forward')
    time.sleep(2)
finally:
    send_command('stop')
```

Запустите `python3 my_brain.py` из папки своей программы. Если робот ещё поднимается,
двух секунд может не хватить для видимого движения — сначала дождитесь стойки.
В реальном коде вместо фиксированного `'forward'` передавайте решение нейросети.
Для клиента используется стандартная библиотека Python, устанавливать PyBullet
в окружение мозга не нужно.

Разрешённые слова: `forward`, `backward`, `left`, `right`, `stop`, `jump`, `normal`,
`start`. Русский текст «иди вперёд» сервер не понимает: ваша программа должна
превратить его в `forward`. Полная таблица — в [технической инструкции](CONTROL_GUIDE.md).

Первое направление запускает движение само. `start` нужен после ошибки: сначала
`start`, потом новое направление. Не отправляйте `start` перед каждой командой.

Если программа мозга закрылась, старая команда продолжает действовать. Поэтому
перед выходом отправляйте `stop`. Если сервер недоступен, отправка stop может не
дойти — откройте работающий интерфейс или остановите процесс сервера.

## 7. Как закончить и как запустить в следующий раз

1. Нажмите **■ Стоп** и дождитесь «Стойка».
2. В первом терминале нажмите **Ctrl+C**. Это выключит сервер симуляции.
3. В следующий раз достаточно:

```bash
cd ~/iron-fly
.venv/bin/python scripts/simulation_ui.py --port 8766
```

Переустанавливать библиотеки каждый раз не надо. Если проект лежит не в `~/iron-fly`,
замените путь на свою папку. Чтобы изменить базовую скорость кнопок, например на
50 мм/с, запустите сервер так:

```bash
.venv/bin/python scripts/simulation_ui.py --port 8766 --brain-speed 0.05
```

В этом параметре используются метры в секунду: 0.1 = 100 мм/с, 0.05 = 50 мм/с.
Максимум базовой скорости — 0.2 м/с. Поворот по умолчанию — 15°/с.

## 8. Что делать на Repka без симуляции

Точная модель Repka и ОС пока неизвестны. Поэтому это порядок пробного запуска,
а не обещание, что всё уже проверено на вашей плате.

Вначале нужна Repka с установленной Linux-системой и доступным терминалом.
Как записать ОС и подключить питание, определяют по инструкции именно вашей
модели платы. Наш проект не является образом ОС.

Скачайте проект, как в пункте 3. В папке проекта выполните:

```bash
bash scripts/bootstrap.sh
python3 -m venv .venv
.venv/bin/python -m pip install PyYAML==6.0.3
bash scripts/build.sh
.venv/bin/python scripts/verify_sources.py
.venv/bin/python tests/test_motion.py
.venv/bin/python tests/test_brain_control.py
.venv/bin/python examples/controller_only.py --seconds 10
```

Результат: в терминале появляются состояние и список из 18 углов. Через 10 секунд
пример завершается. Картинки и движения реальных моторов не будет. Это подтверждает
только то, что вычислительная часть смогла запуститься на устройстве.

В этом варианте PyBullet не устанавливается и браузер не нужен. Но HTTP-сервер
из пункта 5 сюда автоматически не переносится: он включает симуляцию. Для постоянной
работы мозга с реальными приводами ещё нужен отдельный аппаратный сервис.

Если сборка или установка не прошла, сохраните ошибку и результат:

```bash
uname -m
cat /etc/os-release
python3 --version
```

По этим данным можно будет подготовить точную инструкцию для вашей Repka.

## 9. Куда подключать провода и настоящие моторы

**В этой версии — пока никуда по данной инструкции.** Готовой схемы соединения
Repka с приводами здесь нет. Нельзя взять номера из демонстрационного YAML и
считать их проверенной распиновкой вашего робота.

Для следующего этапа понадобятся:

- точная модель Repka и её ОС;
- точная модель платы управления приводами;
- модели сервоприводов и схема их питания;
- размеры ног, нулевые положения и допустимые углы.

После этого можно разработать драйвер, схему подключения и калибровку.
Сейчас от вас требуется программное соединение из пункта 6, а не пайка проводов.

## 10. Если что-то не работает

| Что видно | Что сделать |
|---|---|
| `Repository not found` | Проверить доступ к приватному iron-fly в браузере и авторизацию Git |
| `No such file or directory` | Проверить, что терминал открыт в папке с README.md, scripts и src |
| Нет `.venv/bin/python` | Выполнить `python3 -m venv .venv` в папке проекта |
| `No module named yaml` | Установить зависимости в ту же `.venv`, из которой запускаете программу |
| Не найден `libmuha_fw.so` | Выполнить `bash scripts/build.sh` на текущем устройстве |
| `No matching distribution found` | Сохранить ошибку, версию Python и архитектуру; не менять версии наугад |
| `Address already in use` | На порту уже есть сервер. Открыть его страницу или остановить старый процесс |
| Браузер пишет «Нет связи» | Проверить первый терминал: сервер должен продолжать работать |
| Клиент пишет `Connection refused` | Сначала запустить сервер; проверить порт и устройство |
| После смены скорости числа старые | Перезапустить сервер с новым параметром, обновить страницу |
| Кнопки направления заблокированы | Прочитать причину, устранить её, нажать «Разрешить после ошибки», затем направление |
| Чёрная картинка / WebGL недоступен | Включить аппаратное ускорение браузера и обновить страницу |
| `systemctl` не работает | Использовать прямой запуск из пункта 5; systemd для него не нужен |
| Тесты upstream красные | 25 исходных сбоев документированы; смотреть отдельно собственные проверки |

При обращении за помощью отправьте точную команду, полный текст ошибки, ОС и
версию Python. Не отправляйте токены GitHub или пароли.
